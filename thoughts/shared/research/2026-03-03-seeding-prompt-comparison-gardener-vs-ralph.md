# Research Question

Why do backlog seeding suggestions in Gardener feel weaker than the legacy `scripts/ralph` flow, and what prompt-level differences explain the quality gap?

# Summary

The strongest finding is execution-path mismatch in Gardener. Interactive review-mode seeding uses `recommend_seed_tasks_with_events`, which builds a legacy dry-run prompt that is short and minimally constrained. The richer `seeding-v4` template in `prompt_registry.rs` is used for direct-write seeding, not for dry-run recommendations shown to users. This means the user-visible suggestions are generated by a weaker prompt than expected.

Ralph's refill prompt is opinionated about prioritization and output shape. It provides explicit effort-vs-impact ranking guidance, category framing (quality-grade improvements first, harness/tooling second), anti-duplication warnings, and concrete examples. Those constraints likely produce suggestions that feel more practical and better prioritized.

# Detailed Findings

## Gardener uses two different seeding prompt qualities

- Dry-run recommendations use `build_seed_dry_run_prompt_v1`, which includes only high-level instructions plus quality risks, backlog snapshot, and quality doc.
- Direct-write seeding uses `build_seed_prompt_v2`, which renders `seeding_prompt_template()` with stronger quotas, friction constraints, and anti-hallucination guidance.
- Interactive review mode routes through dry-run recommendations, so users evaluating suggestions mostly see output from the thinner prompt.

## Ralph prompt has stronger ranking and specificity guidance

- Ralph explicitly prioritizes by effort/impact and gives concrete tie-breakers (quick domain-grade wins before complex tooling).
- Ralph defines two work categories and ordering preference when effort is similar.
- Ralph includes concrete formatting expectations and task examples that anchor specificity.
- Ralph adds targeted guardrails for known noisy task classes (TypeScript ESLint suppression cleanup task splitting).

## Additional Gardener prompt quality risks

- Large context injection (full AGENTS/CLAUDE/quality/backlog-skill text) may add noise.
- Seeding template has a minor count ambiguity (`exactly 10` vs `prefer exactly 10`).
- Quality-risk extraction appears broad and may dilute focus if higher-grade rows are treated similarly.

# Architecture Insights

Gardener seeding has bifurcated prompt contracts: a direct-write contract for autonomous insertion and a dry-run JSON contract for recommendation/review UX. Prompt quality currently differs materially between these branches, so UX feedback is dominated by dry-run prompt behavior rather than the richer template.

Ralph used one backlog-refill prompt for the user-observed refill path, so tuning efforts affected exactly what users saw.

# Historical Context

`scripts/ralph` prompt style appears to have influenced Gardener's richer seeding template (`seeding-v4`), but that template is not yet consistently applied to dry-run recommendation mode. This likely creates the perception that quality regressed even though a stronger template exists in the codebase.

# Open Questions

- Should dry-run recommendations switch to `seeding_prompt_template()` with `SEEDING_ACTION_CONTRACT_DRY_RUN` instead of the legacy v1 builder?
- Should dry-run additionally import Ralph-style ranking instructions (effort/impact rubric + quick-win ordering constraints)?
- Should Gardener require per-task evidence references (path/grade/risk) in dry-run output to improve specificity?
